# ピタゴラン試作

コースを組み替えて玉をゴールまで運ぶ、ピタゴラスイッチ系パズルの試作。
物理は [matter-js](https://brm.io/matter-js/)、描画は素の Canvas 2D。

## ▶ 遊ぶ

**https://yokobo103.github.io/yokobo-pitagoran/**

盤面は縦長（540×810）なので、**スマホは縦持ちのまま**遊べる。
`main` に push すると GitHub Actions が自動でビルドして Pages に反映する。

## 手元で動かす

```bash
npm --prefix 20260809_ピタゴラン試作 run dev
```

→ http://localhost:8140

## 遊び方

1. 右のパレットからパーツを選ぶ
2. 盤面をクリック（タップ）で設置
3. **▶ スタート** で玉が転がりだす。カゴに入ればクリア

| 操作 | 効果 |
|---|---|
| パレットをタップ | 置くパーツを選ぶ。**選んだまま何個でも連続で置ける** |
| 盤面をタップ | 設置（10pxグリッドに吸着。Shift押しで自由配置） |
| 置いたパーツをタップ | 選択。**少し外してもいちばん近いパーツを掴む** |
| 置いたパーツをドラッグ | 移動（盤面の外へは出せない） |
| ↩ とりけし | ひとつ前に戻す |
| ホイール / `R` | 回転（PC用） |
| 右クリック / `Delete` | 削除（PC用） |
| `Space` | スタート／もどす |

回転はスライダーと ↺ ↻ ボタン（15°刻み）で行う。**指が盤面を隠さない位置**に
操作を置くのが要点。マウス環境では盤面上に回転ハンドルも出る。

## パーツ

| パーツ | 役割 |
|---|---|
| いた（短）・レール（長） | 道を作る基本。角度が全て |
| ドミノ | 倒れて隣へ伝える。玉が届かない場所に「力」を運ぶ |
| てっきゅう | 重い球。押す・落とす担当。**これがカゴに入ってもクリア** |
| ジャンプ台 | 触れたものを板の向きへ**決まった速さで**打ち上げる |
| トランポリン | **来た勢いをそのまま返す**（1.3倍）。速く当たるほど高く跳ぶ |
| せんぷうき | 前方 230px にずっと風を送る |
| ベルコン | 乗ったものを矢印の向きへ運ぶ。坂を上げられる |
| シーソー | 中央の軸で傾く板（±約29°で止まる）。谷の橋になる |
| ふりこ | 置くのは**軸**。ぶら下がった錘が振れて、当たると弾きとばす |

ステージ側の仕掛け（置くのではなく、盤面に最初からある）:

| 仕掛け | 動き |
|---|---|
| ワープ | 青い渦に入ると桃色の渦から出る。速度はそのまま |
| スイッチ／とびら | 玉がスイッチに触れると、対応するとびらが消える |

## ステージ

1つにつき1つ、新しい仕掛けを覚える構成にしてある。

| # | 名前 | 覚えること |
|---|---|---|
| 1 | 道をつくる | レールをつなぐ。カゴの右半分にはフタがある |
| 2 | ドミノ | 玉が届かない所へ「力」を伝える |
| 3 | 風とジャンプ | 天井があるので、高さと横押しを組み合わせる |
| 4 | トランポリン | 坂では上れない高さへ、跳ね上げて届かせる |
| 5 | ベルコン | 落ちるだけでは届かない所へ運ぶ |
| 6 | シーソー | いたより長い橋を架け、重みで傾かせる |
| 7 | ワープ | 塞がれた壁の向こうへ渦で抜ける |
| 8 | スイッチ | 先にスイッチを通る道を作ってから、とびらを抜ける |
| 9 | ふりこ | 錘の勢いで弾きとばす |
| 10 | 総合 | ワープ → スイッチ → とびら の連鎖を組む |
| 11〜20 | 応用 | 1〜10で覚えた仕掛けの組み替え。18は左右が逆になる |
| — | すきに組む | 全パーツ使い放題のサンドボックス |

全20ステージ、実際にクリアできることを総当たりで確認済み。
正解例は [PROJECT_NOTE.md](PROJECT_NOTE.md) に回帰確認用として全ステージ分ある。

配置はステージごとに localStorage に保存される。

## 中身

```
src/
  parts.js    パーツ図鑑（当たり判定・物理ボディ生成・描画を1か所に）
  stages.js   ステージ台本（固定物・スタート・カゴ・手持ち数）
  game.js     物理世界。配置データから毎回まっさらに組み直す
  render.js   描画。編集中は配置データ、実行中はボディ姿勢を見て同じ絵を描く
  main.js     UI・設置エディタ・再生／リセット
vite.config.js  開発用：POST /__shot で canvas を screenshots/ に保存
```

設計の要は **「配置データ（type/x/y/angle）が正本、物理ボディは毎回そこから生成する使い捨て」**。
リセットが確実に効き、編集画面と実行画面で同じ絵を出せる。

## ブラウザから直接いじる

ブラウザのコンソールから `window.__pita` でコマ送りできる。
rAF が止まる環境（画面非表示）でも物理の当たりを詰められる。

```js
__pita.back(); __pita.load(0); __pita.clear();
__pita.put('rail', 200, 250, 0.25);
__pita.put('rail', 300, 570, 0.35);
__pita.play();
__pita.step(900);   // → { result: 'clear', t: 6.6, ball: {...} }
```

`back()` を挟まずに次の試行を始めると `play()` が早期returnして
**全試行が同じ結果になる**ので注意。

各ステージの正解例は [PROJECT_NOTE.md](PROJECT_NOTE.md) 参照。
